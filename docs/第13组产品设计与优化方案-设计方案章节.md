## 4.2 安全体系设计（修复 3 大 P0 漏洞）

### 4.2.1 问题定位（代码审计结论）

| 编号 | 现状问题（文件定位）                                                                 | 风险等级 |
| ---- | ------------------------------------------------------------------------------------ | -------- |
| S-1  | `SecurityConfig#securityFilterChain` 第 25 行 `.anyRequest().permitAll()` 全放行     | 🔴 高危  |
| S-2  | `JwtUtil` 类有 `validateToken()` 方法，但 **全局无任何地方调用**                     | 🔴 高危  |
| S-3  | `AdminController` 类无 `@PreAuthorize` 或角色判断，普通用户可直接调 `/admin/users`   | 🔴 高危  |
| S-4  | `AdminController` 返回裸 `Map<String,Object>`，字段混乱 `msg` 与 `message` 并存       | 🟡 中危  |

### 4.2.2 安全链路重构方案

#### (1) JwtAuthenticationFilter 新增过滤器

```java
// 位置: com.example.travelmanage.config.JwtAuthenticationFilter
// 核心逻辑: 从 Header 取 Bearer Token → 调 JwtUtil.validateToken()
//   → 有效则提取 username+role 封装 UsernamePasswordAuthenticationToken
//   → 无效则 **清空 SecurityContextHolder** (不直接抛异常, 避免放行路径也报错)
//   → 插入顺序: SecurityConfig 中用 addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)
```

#### (2) SecurityConfig 重写（白名单 + 角色边界）

```
白名单路径（permitAll）:
  /api/auth/**           (登录/注册)
  /api/public/**         (公开浏览: 景区/民宿/餐厅 列表+详情)
  /error
  /uploads/**            (静态图片)
  /doc.html, /v3/api-docs/** (Swagger, 开发环境)

管理员路径（hasRole('ADMIN')）:
  /admin/**

普通用户路径（hasAnyRole('USER','ADMIN')）:
  /api/user/**           (收藏/评论/个人中心)

其他: authenticated()
```

**预期效果（对应安全目标 1-2）：**
- 匿名请求 `/admin/users` → 401 Unauthorized
- 普通用户（role=user）请求 `/admin/users` → 403 Forbidden
- 匿名请求 `/api/public/scenic/1` → 200 正常访问

#### (3) 登录响应 + 前端存储规范

```
登录成功响应:
  Result<{
    token: "eyJhbGciOiJIUzI1NiJ9...",
    userInfo: { id, username, role, phone, avatar }
  }>

前端存储 (localStorage + Pinia userStore):
  key: 'travel_token'    → 后端请求拦截器自动加 Authorization: Bearer xxx
  key: 'travel_user'     → 路由守卫判断 role, 菜单显隐
```

#### (4) 退出登录 / Token 黑名单机制

```
- 后端: Redis SET "jwt:blacklist:{token}" = 1, TTL = Token 剩余过期秒数
- JwtFilter 校验链: validateToken() 合法后 → 再查 Redis 是否在黑名单
- 前端: 清除 Pinia + localStorage, 跳转 /login
```

### 4.4.2 模块 1：搜索 + 多条件筛选（体验目标：关键路径 ≤ 3 步）

| 等级/类型    | level (5A/4A/3A)               | type (大床房/亲子房)          | type (川菜/粤菜)              |
| 评分/热度排序 | popularity DESC / ASC          | score DESC / ASC              | score DESC / ASC              |

**前端交互设计：**

### 4.4.4 模块 3：评论系统（含状态机初版）

**用户写评论流程：**
```
用户点击「写点评」
  → 弹窗: 星星(1-5 必填) + 文本(5-1000字) + 多图上传(≤9张)
  → 提交 POST /api/user/review           status 默认 0=待审核
  → 前端 Toast:「提交成功，等待管理员审核」
  → 后台审核通过后, 该评论才出现在详情页列表 (WHERE status=1)
```

**列表查询接口（防慢查询核心）：**
```sql
-- 走 idx_type_item_status_ctime 联合索引
SELECT r.id, r.rating, r.content, r.create_time, r.like_count,
       u.username, u.avatar,
       (SELECT JSON_ARRAYAGG(image_url ORDER BY sort)
          FROM review_image ri WHERE ri.review_id = r.id) AS images
FROM review r
LEFT JOIN user u ON u.id = r.user_id
WHERE r.item_type = 'scenic_spot'
  AND r.item_id   = 123
  AND r.status    = 1
  AND r.rating   BETWEEN 4 AND 5        -- 好评筛选用
ORDER BY r.create_time DESC
LIMIT 10 OFFSET 0;
```

public void transitionStatus(ScenicSpot spot, Status target, Long auditUserId, String rejectReason) {
    Status cur = spot.getStatus();
    if (cur == DRAFT && target != PENDING_REVIEW) {
        throw new BizException("草稿需先提交审核");   // Result.code = 4003
    }
    if (cur == PENDING_REVIEW && !List.of(PUBLISHED, REJECTED).contains(target)) {
        throw new BizException("待审核只能通过或驳回");
    }
    if (target == REJECTED && (rejectReason==null||rejectReason.isBlank())) {
        throw new BizException("驳回时原因必填");
    }
    spot.setStatus(target);
    spot.setAuditUserId(auditUserId);
    spot.setAuditTime(LocalDateTime.now());
    spot.setRejectReason(rejectReason);
    // ... update
}

## 4.6 代码规范与接口契约统一

### 4.6.1 接口返回 100% 统一为 `Result<T>`

**现状问题（AdminController L22-36）：** 返回裸 `Map`，字段 `code/msg/data` 与 `Result` 的 `code/message/data` 不一致。

**整改要求（全量 Controller 扫描替换）：**

| 改造前（禁止）                          | 改造后（强制）                              |
| --------------------------------------- | ------------------------------------------- |
| `Map<String,Object> + put("code",1) + put("msg",..)` | `return Result.success(data)`               |
| 方法签名无泛型                          | `public Result<List<User>> getUserList(..)` |
| 异常 try/catch 自己塞 code=0            | 直接抛 `BizException` → 全局异常处理器统一包 |
| 分页字段混用 `list/total` vs `records/total` | MyBatis-Plus `IPage<T>` → 序列化后统一 `records/total/pages/current` 四字段 |

**错误码规范（ErrorCode.java 扩展）：**
```
0 / 1              保留(兼容旧)
200                成功 (HTTP 200)
4001               未登录 / Token 无效  (HTTP 401)
4003               无权限 / 角色越权    (HTTP 403)
4004               资源不存在           (HTTP 404)
4005               参数校验失败
4006               状态流转非法
4007               重复操作(已收藏/重名)
5000               系统异常
5001               文件上传超限 / 格式错
5002               Excel 导入行校验错(带 reportId)
```

### 4.6.2 实体类 / DTO 注解规范统一

| 注解位置       | 规范要求                                                  | 示例                                       |
| -------------- | --------------------------------------------------------- | ------------------------------------------ |
| Entity 主键    | `@TableId(type=IdType.AUTO)`                              | `scenic_spot.id`                           |
| Entity 时间字段 | `@TableField(fill=FieldFill.INSERT)` `INSERT_UPDATE` + MetaObjectHandler 自动注入 | `createTime` / `updateTime`                |
| Entity         | `@TableName("xxx")` `@Data` `@NoArgsConstructor`          | 全表必加                                   |
| Entity 字段    | `@TableField("db_col")` 不一致时必加；一致可省略          |                                            |
| DTO 入参       | `@NotBlank` / `@NotNull` / `@Size(max=1000)` / `@Min(1)`  | 写评论 `ReviewAddDTO`                      |
| Controller 方法 | `@PostMapping` + `@Valid` + DTO 接收 + 泛型 Result 返回  | 禁止 `@RequestBody Map`                    |
